<p>几个号共用一个出口，出问题时最难查：不知道是号的问题、段的问题还是时间点的问题。要把它变成可管理的事，得先把"环境"拆成一组能测量的参数，给每个参数定取值、默认值和判定口径。这篇借用硬件说明书的写法，把出口侧、分配侧、切换侧、观察侧四组参数列清楚，每项都写清怎么测、合格线在哪、超出范围意味着什么，最后给三套按账号规模配好的现成组合，照着填就能落地。</p>

<h2>一、这份参数表管什么，不管什么</h2>
<p>管的范围：账号到出口之间的绑定关系、出口本身的属性、异常时的切换规则、以及长期观察需要的记录。不管的范围：账号内容层面的使用行为、平台侧的规则解读，这两块不在本文讨论内。</p>
<h3>为什么参数化比经验靠谱</h3>
<p>经验的问题是没法交接。"那条线挺稳的"这种描述，换个人就没法复用。写成"ASN 为 ISP 类、rDNS 含 broadband、近 30 天无多账号共用记录"，接手人一看就能核对，也不用重新试错。</p>
<h3>三档取值约定</h3>
<p>每个参数标三档：合格、警戒、不可用。合格是可以长期使用的区间，警戒是需要加密观察的区间，不可用是必须更换的区间。三档之间留缓冲，是因为网络属性本身有波动，卡死在单点上会频繁误报。</p>

<h2>二、出口侧的五个可测参数</h2>
<img src="/tp.png" alt="Claude账号纯净住宅IP出口侧的参数测量与合格区间示意">
<p>五个参数里有三个可以直接用命令行查到，另外两个需要供应商侧或历史记录配合。</p>
<h3>ASN 类型</h3>
<p>查 <code>curl -s https://ipinfo.io/json</code>，看 org 字段。归属电信、有线电视、光纤运营商的算 ISP 类；归属云厂商、IDC、CDN 的算机房类。合格：ISP 类。警戒：小型区域运营商，质量波动大。不可用：任何云或 IDC 归属。</p>
<h3>rDNS 特征</h3>
<p>用 <code>dig -x 1.2.3.4 +short</code> 反查。含 dynamic、ppp、broadband、adsl、dsl 之一，说明是家用宽带池。合格：命中上述关键词。警戒：无 rDNS 记录。不可用：反查指向主机商域名。</p>
<p><strong>地址段纯度：</strong>把 IP 送进两三个公开的 IP 信誉查询入口，看是否出现在滥用记录里。合格：近 90 天无记录。警戒：有历史记录但已超过 90 天。不可用：30 天内有新增记录。</p>
<h3>承载账号数</h3>
<p>这是唯一一个必须靠自己的记录来判断的参数。同一条出口下挂的账号数，合格为 1，警戒不留余量，2 个即视为不可用。共用带来的关联风险远大于省下的那点成本。</p>
<p><strong>连续在线时长：</strong>单次连接不中断的时长。合格：连续 7 天以上。警戒：3 至 7 天。不可用：日均断线 2 次以上。这一项决定要不要配备份线路。</p>

<h2>三、分配侧：一号一环境怎么落到参数上</h2>
<p>一号一环境的本质是把三个维度锁死：账号与出口一一对应、账号与设备环境一一对应、账号与常用时段一一对应。</p>
<h3>绑定关系的三条硬约束</h3>
<p>一条出口只挂一个账号；一个账号只走一条主出口加一条备用出口；主备出口必须同城、同 ISP 类型。第三条容易被忽略，主备不同城等于备份线路一启用就跨区，备份反而制造问题。</p>
<h3>备用线路的摆法</h3>
<p>按"双 ISP 轮换备份"摆：主线路运营商 A，备用运营商 B，两条都固定 IP、都归同一城市。备用平时不承载业务流量，只做健康探测，主线路故障时才接管。轮换指按月或按季度互换主备角色，让两条线路都保持活跃状态，避免备用长期不用导致配置生锈。</p>
<h3>时段参数</h3>
<p>给每个账号记一个常用时段窗口，宽度 4 至 6 小时。登录落在窗口内为正常，落在窗口外先记录不告警，连续 3 天都在窗口外才提示复核。这条参数主要服务于交接，让接手人知道该在什么时间用。</p>

<h2>四、切换与回切的参数设定</h2>
<p>切换是自动的，回切必须是谨慎的。自动切换解决可用性，回切解决稳定性，两者规则要分开写。</p>

<h3>为什么要设冷却</h3>
<p>线路抖动往往成串出现，不设冷却会出现一分钟内来回切三次的情况，登录记录上就是两个城市反复跳。冷却期内即使探测失败也不切，宁可短暂不可用，也不要留下跳变痕迹。</p>
<h3>回切为什么比切换严格</h3>
<p>回切意味着把业务从一条正在工作的线路搬回原线路，风险更高。10 次连续成功、30 分钟间隔这两个条件同时满足，才说明原线路真的恢复了，而不是偶然通了两次。</p>

<h3>冗余池怎么用</h3>
<p>冗余池只做替换，不做扩容。某条线路判定不可用时，从池里取一条同城同类型的顶上，取用的那条要立刻补进台账，否则一个月后就说不清哪条线在跑哪个号。</p>
<h3>成本口径</h3>
<p>原生家宽独享出口单条月费大致 80 至 200 元，双 ISP 意味着一号两条，单号月成本约 160 至 400 元（仅供参考）。双 ISP 不一定每条都独享，备用线可以按小时计费，仅在切换时启用，能把成本压到主线的三成左右。</p>

<h2>常见问答</h2>
<h3>一条出口挂两个号真的不行吗？</h3>
<p>答：从参数定义上，承载账号数的合格值就是 1。挂两个号不会立刻出问题，但一旦其中一个号触发异常，另一个会被一并观察。省下的钱通常低于排查和恢复的工时。</p>
<h3>备用线路长期不用会不会失效？</h3>
<p>答：会。长期不承载流量的线路可能出现配置过期、地址回收、会话失效。解决方法就是轮换，按季度把主备互换一次，让两条线都跑过真实流量。</p>
<h3>rDNS 查不到记录就一定不能用吗？</h3>
<p>答：不一定，但属于警戒档。部分运营商对家宽不配置反向解析，这时要结合 ASN 类型和地址段信誉一起看，三项里两项合格可以谨慎使用，三项都不合格就换。</p>
<h3>日志保留 90 天够不够？</h3>
<p>答：多数团队的追溯需求集中在一个季度内，90 天够用。如果账号交接周期更长，比如半年才换一次人，建议把保留期拉到 180 天，存储成本增加有限。</p>
